# poissonsuperlearner software paper replication material

This folder contains replication material for the case studies Poisson Super Learner software paper. This guide describes the supplied materials, software requirements, pipeline execution, and the correspondence between manuscript tables and saved results.

## 1. What this supplement reproduces

Two `targets` pipelines reproduce the numerical analyses for:

- **Table 2**: computation times for piecewise-constant hazard models with linear covariate effects, comparing `Epi`, `pammtools`, and `poissonsuperlearner` across six sample sizes and 10 repeated fits.
- **Table 3**: integrated Brier scores for MGUS2, Rotterdam, and PBC, comparing Cox regression, random survival forests, Poisson Super Learner, discrete Poisson Super Learner, and the individual learners.

The supplement includes saved results and `targets` caches. These allow inspection of the original results without fitting the models again. The R scripts in `code/` provide additional worked examples; they do not need to be sourced before running either pipeline.

## 2. Inspect the supplied results without rerunning

For Table 3, open [the saved LaTeX table](targetts-pipelines/results/main_comparison_integrated_brier_scores.tex) or [the underlying scores](targetts-pipelines/results/main_comparison_maximum_time_scores.csv). The supplied LaTeX file contains the numerical values reported in Table 3, including the Poisson Super Learner scores 0.140, 0.104, and 0.121.

For Table 2, read the cached `timing_summary_xtable` object as shown in Section 6. Its numerical entries match the manuscript table, including mean times of 0.47, 0.61, and 0.14 seconds at sample size 1,000 for Epi, pammtools, and poissonsuperlearner, respectively.

The supplied [computation-time boxplot](figures/pch_computation_time_boxplot.pdf) can also be inspected directly. The other PDFs in `figures/` include manuscript diagrams; the two pipelines do not regenerate all of those assets.

## 4. Data and software requirements

Table 2 uses synthetic data generated by `poissonsuperlearner::simulateStenoT1()` with scenario `alpha` and competing risks. There is one simulated dataset per sample size; each method is fitted 10 times to that same dataset. These are repeated timing measurements, not 10 independently simulated datasets per sample size.

Table 3 uses `survival::mgus2`, `survival::rotterdam`, and `survival::pbc`. The pipeline removes incomplete observations, uses seeded 80/20 training/test splits for MGUS2 and PBC, and uses observations with `year < 1992` for training in Rotterdam. For PBC, death is defined by `status == 2`. METABRIC code is present in the main script, but targets whose names begin with `metabric_` are excluded from the active pipeline. Neither table requires the supplied METABRIC CSV or external data credentials.

Use R 4.1 or later (the benchmark script uses the native anonymous-function syntax) and install the packages used by the pipelines:

```r
install.packages(c(
  "targets", "tidyselect", "data.table", "survival", "riskRegression",
  "prodlim", "randomForestSRC", "xgboost", "glmnet", "mgcv",
  "pammtools", "Epi", "xtable", "remotes"
))
remotes::install_github("gpitt71/poissonsuperlearner", upgrade = "never")
```

If the corresponding poissonsuperlearner source checkout is available locally, it can instead be installed with `remotes::install_local("/path/to/poissonsuperlearner", upgrade = "never")`. This replication folder itself is not an R package. Installing the package from source requires the appropriate R build tools for the operating system.

Optional packages are `crew` for local parallel execution, `crew.cluster` for Slurm workers, and `ggplot2` for plotting. For numerical replication, retain the package versions used for the original analysis where available; installing the current development version does not pin that environment.

## 5. Working directory and pipeline execution

Start R in the supplement root and change into the pipeline directory once:

```r
setwd("targetts-pipelines")
library(targets)
dir.create("results", showWarnings = FALSE)
```

All subsequent R examples assume this working directory. Each `tar_make()` call specifies the script and cache explicitly because neither pipeline script is called `_targets.R`. Keep the two pipelines in separate stores. `tar_read()` needs the store containing the result, but does not need the pipeline script.

### 5.1 Run the Table 2 pipeline

```r
targets::tar_make(
  script = "_targets_pch_comparison.R",
  store = "_targets"
)
```

This builds the simulations, repeated timings, summary statistics, and LaTeX text for Table 2. Run this benchmark sequentially on an otherwise idle machine. The poissonsuperlearner benchmark temporarily enables all data.table threads available to its R process. Hardware, thread availability, system load, and software versions affect the measured times.

### 5.2 Run the Table 3 pipeline

The sequential runner creates the output directory, selects the correct store, and limits numerical-library threads. From a **terminal in the supplement root**, run:

```sh
Rscript targetts-pipelines/scripts/run_main_comparison_local.R
```

This runner locates the pipeline directory from its own file path. Run it with `Rscript`, not `source()`.

Alternatively, from R in `targetts-pipelines/`, run:

```r
Sys.setenv(
  MAIN_COMPARISON_USE_CREW = "false",
  MAIN_COMPARISON_USE_SLURM = "false",
  R_DATATABLE_NUM_THREADS = "1",
  OMP_NUM_THREADS = "1",
  OPENBLAS_NUM_THREADS = "1",
  MKL_NUM_THREADS = "1",
  BLIS_NUM_THREADS = "1",
  VECLIB_MAXIMUM_THREADS = "1",
  NUMEXPR_NUM_THREADS = "1"
)
dir.create("results", showWarnings = FALSE)
targets::tar_make(
  script = "_targets_main_comparison.R",
  store = "_targets_main_comparison"
)
```

Use a fresh R session for these settings. The full comparison includes cross-validation and HAL fits and may take substantial time and memory. Repeating the same command reuses up-to-date cached targets and rebuilds outdated or missing results.

## 6. Obtain Table 2: computation times

From R in `targetts-pipelines/`, retrieve the supplied results, or the results from a completed rerun:

```r
timing_summary <- targets::tar_read(timing_summary, store = "_targets")
print(timing_summary)

table2 <- targets::tar_read(timing_summary_xtable, store = "_targets")
cat(table2, sep = "\n")

# Optional exports: the pipeline stores these objects in the cache.
dir.create("results", showWarnings = FALSE)
data.table::fwrite(timing_summary, "results/table2_computation_times.csv")
writeLines(table2, "results/table2_computation_times.tex")
```

`timing_summary_xtable` is a character vector containing LaTeX, not a file path. The optional exports above create files under `targetts-pipelines/results/`.

The summary reports the mean, standard deviation, median, minimum, and maximum of `elapsed` time in seconds for each method and sample size. The six sample sizes are 1,000, 2,500, 5,000, 10,000, 25,000, and 50,000. The active benchmark compares the three linear-effect models. Although GAM helper functions are defined, they are not included in the active timing targets.

To build just the table and its dependencies:

```r
targets::tar_make(
  names = timing_summary_xtable,
  script = "_targets_pch_comparison.R",
  store = "_targets"
)
```

The generated table has the label `tab:computation_times`, a short caption, and `\code{...}` package labels. To match the manuscript presentation, replace `\code{` with `\pkg{` in the exported text and use the manuscript's longer descriptive caption. For example, the package-label adjustment can be made without editing the pipeline:

```r
table2_manuscript <- gsub("\\code{", "\\pkg{", table2, fixed = TRUE)
writeLines(table2_manuscript, "results/table2_computation_times.tex")
```

The manuscript's LaTeX class must provide the corresponding macros. Exact original timing values are obtained from the supplied cache; a fresh benchmark measures the current machine.

## 7. Obtain Table 3: integrated Brier scores

The full main-comparison run writes:

| Target | File under `targetts-pipelines/results/` | Contents |
|---|---|---|
| `integrated_brier_scores_latex` | `main_comparison_integrated_brier_scores.tex` | Table 3, with scores printed to three decimal places |
| `maximum_time_scores_csv` | `main_comparison_maximum_time_scores.csv` | Scores and maximum evaluation times in long format |
| `computation_times_csv` | `main_comparison_computation_times.csv` | Fit timings for the real-data comparison; these are separate from Table 2 |

To build only Table 3 and its underlying score CSV, first apply the sequential settings in Section 5.2, then run:

```r
dir.create("results", showWarnings = FALSE)
targets::tar_make(
  names = c(integrated_brier_scores_latex, maximum_time_scores_csv),
  script = "_targets_main_comparison.R",
  store = "_targets_main_comparison"
)
```

The required training, fitting, prediction, and scoring targets run automatically. Retrieve the table and inspect the numerical results with:

```r
table3_path <- targets::tar_read(
  integrated_brier_scores_latex,
  store = "_targets_main_comparison"
)
cat(readLines(table3_path), sep = "\n")

scores <- targets::tar_read(
  maximum_time_scores,
  store = "_targets_main_comparison"
)
print(scores)
```

Unlike Table 2's LaTeX target, `integrated_brier_scores_latex` is a file target, so `tar_read()` returns a path. The three dataset-specific summaries are `mgus_maximum_time_score`, `rotterdam_maximum_time_score`, and `pbc_maximum_time_score`.

The pipeline computes `riskRegression::Score(..., metrics = "brier", summary = "ibs")` on the test data and selects `IBS` at the largest evaluation-grid time. The grids use 24-month steps for MGUS2 and 365-day steps for Rotterdam and PBC. Their endpoints need not equal the largest observed follow-up time exactly. Accordingly, the generated caption says **"maximum evaluation time"**, whereas the manuscript caption says **"maximum follow-up time"**. To reproduce the manuscript wording in an exported copy:

```r
table3_manuscript <- sub(
  "maximum evaluation time", "maximum follow-up time",
  readLines(table3_path), fixed = TRUE
)
writeLines(table3_manuscript, "results/table3_manuscript.tex")
```

The table target selects the 11 manuscript models in the required order and omits any null-model row in the scoring output. Its label is `tab:integrated-brier-scores`. Table numbering is assigned when the exported table is included in the manuscript.

## 8. Optional parallel execution of the main comparison

For local workers, install `crew`. In a **terminal in `targetts-pipelines/`**, run:

```sh
Rscript scripts/run_main_comparison_crew_local.R
```

This defaults to two workers. Set `MAIN_COMPARISON_CREW_WORKERS` before launching to change the worker count. Both local runners support `MAIN_COMPARISON_TARGETS`, a comma-separated list of target names; leaving it unset runs the full pipeline. They share the `_targets_main_comparison` store. Do not run multiple processes against that store simultaneously.

For a Slurm cluster, install `crew` and `crew.cluster`, configure the site's resources, and run `Rscript scripts/run_main_comparison_slurm.R` from `targetts-pipelines/`. Its settings include `MAIN_COMPARISON_SLURM_WORKERS` (default 4), `MAIN_COMPARISON_SLURM_PARTITION` (default `long`), `MAIN_COMPARISON_SLURM_MEMORY_GB` (48 per worker), `MAIN_COMPARISON_SLURM_CPUS` (1), and `MAIN_COMPARISON_SLURM_TIME_MINUTES` (1440).

The separate `scripts/submit_main_comparison.sh` submits one allocation and runs local crew workers inside it. Its partition and node directives are site-specific. These cluster launchers are optional; the sequential runner is sufficient for Table 3. Keep Table 2 sequential for interpretable benchmark timings.

## 9. Cache inspection and a fresh rerun

Use the supplied caches for spot checks and the original table values. For example:

```r
targets::tar_read(timings, store = "_targets")
targets::tar_read(mgus_maximum_time_score, store = "_targets_main_comparison")
targets::tar_meta(
  fields = c(name, error, warnings),
  store = "_targets_main_comparison"
)
```

The main pipeline uses `error = "continue"`, so independent targets can finish after another target fails. Check the error metadata if a requested table is not produced, resolve the reported problem, and rerun the same command.

For a fresh rerun that preserves the supplied caches, choose new stores:

```r
targets::tar_make(
  script = "_targets_pch_comparison.R",
  store = "_targets_pch_fresh"
)
# Apply the sequential settings in Section 5.2 before this call.
targets::tar_make(
  script = "_targets_main_comparison.R",
  store = "_targets_main_fresh"
)
```

Use the corresponding new store in subsequent `tar_read()` calls. The main pipeline still writes to the same `results/` filenames, so copy the original exports elsewhere first if they need to be retained. No cache deletion is needed for a routine rerun.

The optional `scripts/plot_pch_comparison.R` contains an author-specific absolute output path and reads from the default store, despite defining a separate `store` variable. It is not needed to obtain either table; inspect the supplied boxplot directly or plot the `timings` object in a separate R session.
